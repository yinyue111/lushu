# 邮箱改造设计（feat/login 之上）

日期：2026-10-10　　分支：feat/login（本地，未推送）

## 1. 要解决什么

1. 注册时必须留邮箱，并且收到验证码、填对之后账号才建出来。
2. 忘了密码，可以用邮箱收验证码重设；原来的恢复码保留，作为没有邮箱时的后备。
3. 邮箱和手机号都能登录。
4. 登录状态下生成的路书都存进账号，换设备、换浏览器登录还能看到，可以查看、删除、导出。

## 2. 现状（改之前先看清楚）

- 账号：手机号 + 密码。手机号只存 HMAC（查重/查找）和打码后的样子，不存明文。
- 路书：生成任务 `POST /api/generation-jobs` 在服务端用 `generateAndStoreRoutebook` 直接落库，`profileId` 由 `resolveWriteProfile` 决定。**登录后它已经是账号的主档案**，所以"生成的路书存进账号"在服务端其实已经成立；「我的」页也会按档案去云端拉路书。
- 缺口：①只能删本机存档，删不掉云端那份；②认领进账号的旧设备档案名下、没带编辑令牌的路书，列表里看不到；③页面上没说清"这些路书已存进账号"。
- 游客草稿在登录时通过 `/api/auth/claim` 用编辑令牌认领，这条路沿用。

结论：路书部分不另起一套存储，复用现有的路书流和档案归属，只补"列出账号所有档案的路书""云端删除""明确提示"。

## 3. 关键决定

### 3.1 邮箱怎么存

- 规范化：去首尾空格、全角转半角、整串转小写（域名本来就不分大小写；本地部分理论上分，但实际几乎没有邮箱服务这么做，统一小写能避免"大小写不同就注册两个号"）。不去掉 Gmail 的点和 `+tag`：那是用户自己的选择，乱合并会把两个人合到一起。长度上限 254，格式只做基本校验（有一个 @、域名带点、无空白）。
- 存三样：
  - `email_hash`：HMAC-SHA256（密钥 `AUTH_EMAIL_HASH_SECRET`，没配就用手机号的那把派生），用来查找和唯一约束。
  - `email_enc`：AES-256-GCM 加密后的邮箱（密钥 `AUTH_EMAIL_ENC_KEY`）。发信必须知道邮箱原文，所以不能只存哈希；加密而不是明文，是为了数据库/备份泄露时不直接暴露邮箱。
  - `email_masked`：打码展示用，如 `ab***@qq.com`。运维后台和「我的」只显示这个。
- 为什么不直接存明文：手机号已经按"不存原文"处理，邮箱同样是个人信息，保持一致；代价只是多一把密钥，运维上可接受。
- 唯一：一个邮箱只能属于一个未注销的账号（PG 部分唯一索引；JSONL 在写入时检查）。

### 3.2 注册流程

- **邮箱必填，手机号改为选填。** 理由：邮箱现在能找回密码，比手机号更有用；我们不发短信，手机号本来就只是登录名，强制填反而劝退。已经填了手机号的老账号照旧能用手机号登录。
- 两步：
  1. 填邮箱 → 「发验证码」（需过轻量人机检查）。服务端**不管邮箱是否已注册都回"已发送"**；已注册的邮箱收到的是"有人用你的邮箱注册，如果是你，直接登录或重设密码"，不泄露账号是否存在。
  2. 填 6 位验证码 + 密码（+ 选填手机号、邀请码、同意隐私）→ 校验通过才建账号，`email_verified_at` 记为当时。没有"未激活账号"这种中间状态，省掉清理逻辑。
- `EMAIL_VERIFICATION_REQUIRED=false`（只在发信还没配好的过渡期用）：注册可以不填验证码，账号照建，邮箱标"未验证"，之后在「我的 → 账号」里补验证。未验证的邮箱**不能**用来重设密码，也不能用来登录（防止有人用别人的邮箱先注册占位）。

### 3.3 验证码

- 6 位数字，15 分钟有效，单次使用，存的是 HMAC 哈希不是原文。同一邮箱同一用途再发新码时，旧码作废。
- 每个码最多试 5 次，超过作废；另外按邮箱累计错误走锁定（沿用现有节流表）。
- 用途：`register`（注册）、`reset`（重设密码）、`change`（添加/换邮箱）。码和用途、邮箱绑定，不能串用。

### 3.4 登录

- 一个输入框「手机号或邮箱」：含 @ 当邮箱，否则当手机号。
- 不存在的账号和密码错，返回同一句"账号或密码不对"，同样做一次 scrypt，耗时一样。
- 节流键按标识符哈希（邮箱用 `email:` 前缀，手机号沿用 `phone:`），加 IP 维度，沿用现有锁定策略。
- 只有已验证的邮箱能登录。

### 3.5 忘记密码

- 首选：邮箱收验证码 → 填码 + 新密码。发码接口对任何邮箱都回"如果这个邮箱绑定了账号，验证码已发出"。
- 后备：恢复码（原样保留，现在可以配手机号或邮箱）。
- 重设成功：所有设备的登录都退出，当前设备重新登录；给邮箱发一封"密码已重设"通知。

### 3.6 添加/更换邮箱

- 在「我的 → 账号」：输入新邮箱 + 当前密码 → 给新邮箱发码 → 填码确认。
- 换成功后给**旧邮箱**发通知（"你的账号邮箱已改为 ne***@…，如果不是你本人，请用恢复码重设密码"）。
- 老的纯手机号账号：登录后在账号区和登录成功后看到"加个邮箱，忘了密码能自己找回"的提示，**不强制、不锁号**。

### 3.7 发信

- 抽象成 `sendMail({ to, subject, text })`，按 `MAIL_TRANSPORT` 选：
  - `file`（开发和测试默认）：写到 `data/mail-outbox/*.json`，不发真信。E2E 从这里读验证码。
  - `log`：只在服务日志里记"已发给 ab***@qq.com"，不打印验证码；用于没有信道的环境。
  - `resend`：Resend HTTP API（`MAIL_API_KEY`），用内置 fetch，不加新依赖。
  - `smtp`：本次**不实现**（要引入 nodemailer，会多一个依赖和审计面），留给用户决定。
- 生产缺少发信配置而 `EMAIL_VERIFICATION_REQUIRED=true` 时，启动自检报错，避免注册全挂。
- 发送节流：每个邮箱 1 小时最多 5 封、两次间隔至少 60 秒；每个 IP 1 小时最多 20 封。超出返回"发得太频繁了，X 分钟后再试"。

### 3.8 数据迁移 0009（只加不改）

- `auth_users` 新增：`email_hash`、`email_enc`、`email_masked`、`email_verified_at`；`phone_hash`/`phone_masked` 放开 not null（因为手机号改为选填）。新的部分唯一索引 `email_hash where status<>'deleted' and email_hash is not null`。
- 新表 `auth_email_codes`：id、purpose、email_hash、email_enc、user_id、code_hash、attempts、expires_at、consumed_at、created_at。
- JSONL 后端：`accounts.jsonl` 增加 `code` 行类型。PG 与 JSONL 共用一份契约测试。
- 回滚：把 `AUTH_MODE` 改回 `access-code` 即可，新列/新表留着不用；旧代码不读这些列，不受影响。

### 3.9 路书存进账号

- 列表：`GET /api/routebooks?profileId=<主档案>` 在登录状态下，会把账号认领过的所有档案的路书一起列出来。
- 删除：新增 `DELETE /api/routebooks/:id`，只有登录且拥有这本路书的账号能删；写一条带 `deletedAt` 的新版本（日志只追加），列表和读取都会过滤。「我的」里删除时，登录用户删的是云端+本机，未登录照旧只删本机。
- 导出：现有「导出账号数据」已包含各档案下的路书，不再新增。
- 游客认领：沿用 `/api/auth/claim`。

### 3.10 其他

- 隐私说明：新增"邮箱"一节——用途（登录、验证码、找回密码、账号安全通知）、加密存储、不做营销、注销即删除、发信服务商（待定）。
- 运维账号页：显示打码邮箱和"已验证/未验证"，可按完整邮箱搜索（按哈希比对）。
- 生成中页面：补一个 h1（现在只有 h2）。

## 4. 新环境变量

| 变量 | 说明 | 默认 |
|---|---|---|
| `MAIL_TRANSPORT` | `file` / `log` / `resend` / `disabled` | 开发 `file`，生产必须显式配置 |
| `MAIL_FROM` | 发件人，如 `路书 <no-reply@example.com>` | 无 |
| `MAIL_API_KEY` | Resend 的 API key | 无 |
| `MAIL_OUTBOX_DIR` | file 模式写信目录 | `data/mail-outbox` |
| `AUTH_EMAIL_HASH_SECRET` | 邮箱 HMAC 密钥 | 生产必填 |
| `AUTH_EMAIL_ENC_KEY` | 邮箱加密密钥（32 字节 base64/hex） | 生产必填 |
| `EMAIL_VERIFICATION_REQUIRED` | 注册是否必须验证邮箱 | `true` |

## 5. 需要用户拍板

1. 用哪个发信服务、发件域名（Resend / 阿里云邮件推送 / 腾讯云 SES / 自建 SMTP），并配置 SPF/DKIM。国内收件（QQ、163）送达率差异大，建议国内服务商。
2. 手机号改成选填是否同意。
3. 是否需要 SMTP（要加 nodemailer 依赖）。

## 补充：删除的路书不会“复活”

以前从账号里删掉一份路书，只是追加一条带删除时间的记录；另一台设备还留着旧副本，下次同步就会把它重新存回去。现在：

- 删除时追加一条“墓碑”：只记路书 ID、所属档案、删除时间，不再保留路书内容。
- 之后任何设备、任何方式（保存、补传本机副本、改路线、发布、加方案、认领）再写这个 ID，服务器一律回 410 `ROUTEBOOK_DELETED`，并带上 ID；换个账号、用编辑令牌也不行。读取也回 410，而不是笼统的“不存在”。
- 前端收到 410 就把本机副本删掉，不会当成“冲突副本”保留，并提示“这份路书已经从账号里删除了，本机的副本也已移除”。
- 打开应用、网络恢复、切回页面时，前端把本机同步过的路书 ID 发给 `POST /api/routebooks/deleted`，服务器只回答哪些已删除，本机随即清掉。
