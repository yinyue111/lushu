# 文案规范（用户侧）

`npm run verify` 会跑 `npm run lint:copy`（`scripts/copy-lint.mjs`），按下面第 1、2 条自动检查 `src/` 下的 UI 文案。

1. 称呼用「你」，不用「您」；不用感叹号（全角「！」不用，半角「!」不紧挨中文）。
2. 术语：信息是否可靠，一律叫「核对」（待核对 / 已核对）；不用 验证 / 校验 / 审核 / 核验 / 校准。
   例外：「验证邮箱」「验证码」（账号流程的专有说法，含「邮箱未验证 / 邮箱已验证」）；
   `src/components/Legal/` 法务页面照录法规流程原词（法务审核、内容安全审核、短信验证），不受此条约束；
   管理后台（`admin/`）不在扫描范围。
3. 状态名以 v4 那套为准：核对中、已核对、已反馈待复核、人工核实、待确认。不要另造近义词。
4. 发布不是核对：申请公开用「申请公开」，提交后写「已申请公开」；只有代码真的会通知用户时，才能写「处理好会通知你」。
5. 不出现模型名或供应商名；需要提到时写「AI」。
6. 标点：中文语境用全角 ，。：；？（）「」…；成句的说明以句号结尾，按钮 / 标签 / 标题不加句号。
7. 数字和单位之间加空格：约 10 分钟、0.8 km、300 m、2 天 1 晚、第 1 天；约数用「约」，不用 ~。
8. 按钮用「动词 + 对象」，2–6 个字：排一条路线、存一份、改成我的、复制朋友链接。
9. 出错三段式：发生了什么 → 你的东西还在吗 → 下一步。不透出原始错误信息。网络错误统一用
   `src/lib/networkCopy.js` 里的句子；`public/sw.js` 离线兜底页与它保持一致（有单测）。
10. 空状态 = 一句现状 + 一个下一步按钮。
11. 不可逆操作的确认句写清后果和能否撤销：「删掉…？可以撤销。」
12. 只写真实的事：写「会自动同步 / 会通知你 / 会保存」之前，先确认代码真的这么做；拿不准的信息标「待确认」。

## 豁免

确实需要例外时，在同一行或上一行写 `// copy-lint-ignore <理由>`（JSX 里写 `{/* copy-lint-ignore <理由> */}`）。
理由必填，空理由本身会报错。
